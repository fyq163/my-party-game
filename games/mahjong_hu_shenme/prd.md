# 麻将胡什么 · PRD

> 状态：草稿骨架。规则、玩法、design 由用户补全，技术约束先行锁定。

## 1. 一句话

大屏幕上给出一副手牌，现场玩家猜“胡什么”（能胡哪几张），主持人揭晓并计分。

## 2. 场景与角色

- 大屏 + 主持人 + 现场观众/选手，线下口头或举牌作答，大屏只负责出题、揭晓、计分。
- 单轮时长目标：1～2 分钟（待用户确认）。

## 3. 游戏规则（用户填写）

- 题型：给出几张手牌（13 张待胡？还是多面听牌型）——
- 牌型范围：只用筒/条/万？是否含字牌（东南西北中）？是否含花——
- 胡牌判定：是否考虑番型/只看能不能胡——
- 答案形式：猜全部进张 / 猜其中一张 / 抢答——
- 计分：答对得分、答错扣分、轮空怎么算——

## 4. 玩法流程（用户填写）

- 出题 → 作答（限时？抢答？）→ 揭晓（高亮进张）→ 计分 → 下一题。
- 一局几题、胜负条件——

## 5. Design（用户填写）

- 大屏布局：手牌区 / 标题区 / 计分区 / 倒计时——
- 视觉风格：沿用现有牌面（白底细灰描边圆角 120×168），背景、字体、配色——
- 动效音效：发牌、揭晓、答对/答错反馈——

## 6. 技术实现（已锁定，开发照此做）

- Tauri + Web 前端；本游戏是纯前端页面，无后端。
- 牌面资源：复用 `assets/mahjong/tiles/*.png`，以 `assets/mahjong/manifest.json` 的 `id`
  （`{suit}_{rank}`，如 `tiao_8`、`wind_east`、`dragon_red`）为准按需加载。
- 出题/判胡逻辑放前端 TS 模块，保持可单元测试（规则函数与渲染分离）。
- `rundown.yaml` 条目示例：

```yaml
- kind: game
  game: mahjong_hu_shenme
  title: 麻将胡什么
```

## 7. 验收标准

- 大屏 1080p 下手牌清晰可辨，3 米外能看清牌面。
- 一题完整流程（出题→作答→揭晓→计分）可跑通。
- 换题不重启应用；整场不闪退。
